    開始之前：裝好 Unity，寫出第一支腳本

    這一關不用寫太多程式。目標是把工具裝好、認得 Unity 的幾個視窗，並讓 Console 印出第一行字。

    這本手冊怎麼用

    • 每一關的順序都一樣：概念 → 程式碼範例 → 常見錯誤 → 動手練習 → 小測驗。
    • LV.01 到 LV.03 會把 Python 和 C# 並排對照，你會 Python，就能很快抓到差別。
    • 程式碼右上角有「複製」按鈕，可以直接貼進 Unity 的 .cs 檔。
    • 讀完一關就按「標記完成」，頂部的經驗條會累積。進度只存在這台電腦的這個瀏覽器裡。

    安裝三樣東西

    1. Unity Hub：到 unity.com/download 下載。它負責管理 Unity 版本和專案。
    2. Unity 6 LTS（版本號是 6000.x）：在 Hub 的 Installs → Install Editor 安裝。建議選 LTS，教學和套件最穩定。
    3. 程式編輯器：安裝 Unity 時勾選 Visual Studio Community 最省事。想用 VS Code 也可以，要另外裝 C# Dev Kit 和 Unity 擴充套件，再到 Unity 的 Edit → Preferences → External Tools 把編輯器設成 VS Code。

    建立 2D 專案

    在 Hub 按 New project，範本選 Universal 2D（URP 的 2D 版本），取個名字（建議用英文路徑，例如 D:\UnityProjects\MyFirst2D），按 Create。

    第一次開啟會花幾分鐘匯入資源，這是正常的。

    Hierarchy目前場景裡所有物件的清單，可以有父子層級資料夾樹

    LV.01 · C# 基礎 I

    變數與型別

    Python 會自己猜變數是什麼型別，C# 要你先講清楚。多打幾個字，換來的是：打錯型別時，還沒開始玩就會被抓出來。

    同一段邏輯，兩種寫法

    你應該已經看到四個差別：

    • 變數前面要寫型別：int、float、string、bool。
    • 每一行結尾要加分號 ;。
    • true / false 是小寫。
    • f-string 在 C# 寫成 $"..."，大括號用法一樣。

    遊戲裡最常用的型別

    型別存什麼例子遊戲裡拿來
    int整數int coins = 0;分數、生命數、關卡編號
    float小數，數字後面加 ffloat speed = 3.5f;速度、位置、時間、血量比例
    bool真或假bool isGrounded = false;有沒有落地、遊戲是否結束
    string文字，用雙引號string tag = "Player";名稱、對話、UI 文字
    char單一字元，用單引號char grade = 'A';比較少用

    為什麼 float 要加 f？C# 裡 5.5 預設是 double（更精確的小數），而 Unity 的位置、速度全部用 float。寫 5.5f 是告訴 C#「這是 float」。

    偷懶寫法 var：var coins = 0; 會自動推斷成 int。型別還是固定的，只是不用自己寫。初學時建議先把型別寫出來，比較好讀。

    命名習慣：Python 用 is_alive（snake_case），C# 的變數用 isAlive（camelCase），class 和方法用 PlayerController、TakeDamage（PascalCase）。

    運算子

    用途PythonC#注意
    整數除法7 // 2 → 37 / 2 → 3兩邊都是 int 就會捨去小數
    一般除法7 / 2 → 3.57 / 2f → 3.5有一邊是 float 才有小數
    餘數7 % 27 % 2一樣
    加一x += 1x++; 或 x += 1;C# 有 ++ 和 --
    且 / 或 / 不是and or not&& || !最常打錯的地方
    相等 / 不相等== !=== !=一樣

    建立腳本 Stats，掛到任何物件上按 Play。寫在方法外面的變數叫做欄位（field），整個 class 都能用，類似 Python class 裡的 self.coins。

    • 小數沒加 f：float speed = 5.5; 會得到這個錯誤：
    • 忘記分號：錯誤代碼 CS1002: ; expected。括號裡的數字 (6,25) 是「第 6 行第 25 個字」，直接跳過去看。
    • 寫成 Python 的 True：C# 只認得小寫的 true。
    • 字串用單引號：'abc' 在 C# 是錯的，單引號只能放一個字元。
    • 以為 1 / 3 是 0.333：兩個整數相除會得到 0。要寫 1f / 3f。

    LV.02 · C# 基礎 II

    條件判斷與迴圈

    邏輯和 Python 一模一樣，差在外觀：Python 靠縮排分區塊，C# 靠大括號 { }，條件要放在小括號 ( ) 裡。

    if / else 與 for

    elif 在 C# 是 else if。C# 的縮排只是為了好讀，真正決定區塊的是大括號。

    for 的三段：for (起始; 條件; 每圈結束後做的事)。for (int i = 0; i < 3; i++) 就是 Python 的 range(3)：從 0 開始，小於 3 就繼續，每圈加 1。

    foreach、while 和 switch

    最後一行是三元運算子：條件 ? 成立時 : 不成立時。switch 適合「一個值對應很多種情況」，例如武器種類：

    常見錯誤大括號和迴圈

    • if 後面多一個分號：if (hp <= 0); 分號會讓 if 直接結束，下面的大括號永遠會執行，而且不會報錯。
    • 把 == 寫成 =：if (hp = 0) 在 C# 會編譯錯誤，看到 CS0029 先檢查這裡。
    • 在 Update() 裡寫 while 等待事情發生：例如 while (!isGrounded) { }。Unity 會整個卡死，只能強制關閉。Update() 本身每幀都會跑，它已經是一個迴圈了；要等待請用 if 判斷，或之後會教的協程。
    • switch 的 case 忘了 break：C# 不允許自動掉到下一個 case，會出現 CS0163。

    LV.03 · C# 基礎 III

    陣列、List、方法與類別

    這一關學會怎麼裝一堆資料、怎麼把程式包成方法，以及 class 的寫法。學完這關，就能讀懂大部分的 Unity 腳本。

    陣列和 List

    陣列長度固定：int[] scores = new int[3]; 或 string[] names = { "Ann", "Bo" };，長度用 .Length。

    List 可以增減，最像 Python 的 list。要先在檔案最上面加 using System.Collections.Generic;。尖括號裡寫「裝什麼型別」：List<string> 只能裝字串。

    Python 的 dict 對應 C# 的 Dictionary<string, int>，例如 inventory["potion"] = 3;。

    方法（函式）

    方法名稱前面寫的是回傳型別：int Heal(...) 會回傳 int。void 代表不回傳任何東西。每個參數也要寫型別。

    Mathf 是 Unity 的數學工具箱：Mathf.Min、Mathf.Max、Mathf.Abs、Mathf.Clamp 之後會一直用到。

    類別與物件

    PythonC#說明
    __init__和 class 同名的方法叫做建構子，建立物件時執行
    selfthisC# 大多可以省略，只有名稱衝突時才要寫
    Enemy(...)new Enemy(...)建立物件要加 new
    名字前加 _ 當作私有privateC# 會真的禁止外部存取

    public 和 private：public 的成員其他腳本可以用，private 只有自己 class 裡能用。沒寫的話預設是 private。好習慣是：能 private 就 private，需要給別人用的才 public。

    重點預告：在 Unity 裡，掛在物件上的腳本不能用 new 建立，下一關會說明原因。

    常見錯誤集合和方法

    • 索引超出範圍：3 個元素的陣列，最後一個是 [2]。存取 [3] 會得到 IndexOutOfRangeException（List 則是 ArgumentOutOfRangeException）。
    • 陣列和 List 的長度屬性搞混：陣列用 .Length，List 用 .Count。
    • 忘了 using：用了 List 卻沒寫 using System.Collections.Generic;，會看到 CS0246: The type or namespace name 'List<>' could not be found。
    • 有回傳型別卻沒 return：int Heal() 裡某條路徑沒有 return，會看到 CS0161: not all code paths return a value。

    動手練習還有幾隻怪活著？

    寫一個方法 int CountAlive(List<int> hpList)，回傳血量大於 0 的數量。在 Start() 用 { 10, 0, 5, -3, 8 } 測試，應該印出 3。

    LV.04 · Unity 核心

    GameObject、元件與生命週期

    Unity 不是從 main 開始一路往下跑。它是「物件身上掛元件，Unity 在對的時機呼叫元件的方法」。理解這一點，後面全部都會變簡單。

    GameObject 是空盒子，元件才是功能

    Hierarchy 裡的每一個東西都是 GameObject，它本身什麼都不會。功能來自掛在身上的元件（Component）：

    元件負責
    Transform位置、旋轉、縮放。每個物件一定有
    SpriteRenderer畫出 2D 圖片
    Rigidbody2D受重力、有速度，讓物理引擎接管
    BoxCollider2D碰撞的形狀
    你寫的腳本遊戲邏輯。只要繼承 MonoBehaviour 就能當元件掛上去

    所以腳本的 class 一定寫成 public class Player : MonoBehaviour，冒號是「繼承」。也因為腳本是元件，不能用 new Player() 建立，要用拖曳或 AddComponent<Player>() 掛到物件上。

    Unity 什麼時候呼叫你的方法

    Awake→ OnEnable→ Start→ 每幀重複 FixedUpdate→ Update→ LateUpdate → OnDisable→ OnDestroy
    方法什麼時候適合做
    Awake()物件一載入就執行，最早用 GetComponent 抓自己身上的元件
    Start()第一次 Update 之前，一次需要其他物件已經準備好的初始化
    Update()每一幀，次數依影格率而定讀取輸入、計時器、一般邏輯
    FixedUpdate()固定間隔，預設每 0.02 秒操作 Rigidbody2D 的物理移動
    LateUpdate()所有 Update 跑完之後攝影機跟隨角色
    OnDestroy()物件被刪除時收尾、取消訂閱

    Inspector 欄位與 GetComponent

    加上 [SerializeField] 的 private 欄位會出現在 Inspector，可以不改程式就調整數值。public 欄位也會出現，但其他腳本也能亂改它，所以一般建議 [SerializeField] private。

    試法：Hierarchy 右鍵 → 2D Object → Sprites → Square，把 Spinner 拖上去，按 Play。在 Inspector 改 Speed 看看。

    想用別的物件，宣告 [SerializeField] private Transform target;，再到 Inspector 把那個物件拖進欄位。這是 Unity 最常見的「接線」方式。

    常見錯誤沒報錯但不會動

    • 方法名稱大小寫打錯：void update() 或 void start() 不會報錯，但 Unity 找不到它，所以永遠不會執行。
    • NullReferenceException：最常見的執行錯誤，代表你用了一個空的參考。通常是 Inspector 欄位忘了拖東西進去，或物件身上根本沒有那個元件。雙擊錯誤會跳到出錯的那一行。
    • 改了程式裡的預設值卻沒效果：欄位一旦出現在 Inspector，Inspector 的值優先。在元件右上角 ⋮ 選 Reset 才會回到程式裡的預設值。
    • 每幀呼叫 GetComponent：可以用，但浪費效能。在 Awake() 抓一次存起來。

    動手練習閃爍方塊

    寫一個 Blinker 腳本：每 interval 秒（預設 0.5，可在 Inspector 調）切換一次 SpriteRenderer.enabled，讓方塊一閃一閃。提示：用一個 float 計時器累加 Time.deltaTime。

    LV.05 · 輸入與移動

    讀鍵盤、讓角色動起來

    這一關把鍵盤輸入轉成移動。最重要的觀念只有一個：移動量要乘上 Time.deltaTime。

    位置與向量

    物件位置是 transform.position，型別是 Vector3（x, y, z）。2D 遊戲只用 x 和 y，z 通常是 0。Unity 的單位是「公尺」，預設一張 100 像素的圖等於 1 單位。

    Vector2 是只有 x、y 的向量，可以自動轉成 Vector3。常用的有 Vector2.right（1, 0）、Vector2.up（0, 1）。

    為什麼要乘 Time.deltaTime

    Time.deltaTime 是「上一幀花了幾秒」。60 FPS 時大約 0.0167，144 FPS 時大約 0.0069。

    如果每幀固定移動 0.1，144Hz 螢幕的玩家會跑得比 60Hz 快 2.4 倍。寫成 speed * Time.deltaTime，speed 的意思就變成「每秒移動幾單位」，任何電腦都一樣快。

    小測驗輸入與移動

    LV.06 · 2D 物理

    重力、跳躍與碰撞

    平台遊戲的手感來自物理。這一關讓角色受重力、站在地上、按空白鍵跳起來，並且知道自己撞到了什麼。

    兩個元件：Rigidbody2D 和 Collider2D

    設定意思用在
    Body Type: Dynamic受重力和碰撞推動玩家、會掉落的箱子
    Body Type: Kinematic不受重力，由程式控制位置移動平台、巡邏的敵人
    Body Type: Static完全不動地板、牆壁
    Gravity Scale重力倍率，平台遊戲常設 3 到 4讓跳躍不會飄
    Constraints → Freeze Rotation Z不讓物件被撞得旋轉玩家一定要勾

    Collider2D 決定碰撞形狀：BoxCollider2D、CircleCollider2D、CapsuleCollider2D（角色最常用，不容易卡在地板接縫）。勾選 Is Trigger 後就不會擋住東西，只會「偵測到有東西進來」。

    平台角色：移動和跳躍

    有了 Rigidbody2D，就不要再用 transform.Translate，改成設定速度 linearVelocity（Unity 6 的名稱，舊版叫 velocity）。輸入在 Update 讀，物理在 FixedUpdate 做。

    場景設定步驟

    1. 右上角 Layers → Edit Layers，新增一個 Layer 叫 Ground。地板物件的 Layer 改成 Ground，並加上 BoxCollider2D。
    2. 玩家加上 Rigidbody2D（勾 Freeze Rotation Z）和 CapsuleCollider2D，再掛 PlatformerMove。
    3. 在玩家底下建立空的子物件 GroundCheck，移到腳底。拖進腳本的 Ground Check 欄位。
    4. Ground Layer 欄位選 Ground。選取玩家時，Scene 視窗會畫出檢測圓，確認它剛好碰到地面。

    撞到東西：Collision 和 Trigger

    事件條件效果例子
    OnCollisionEnter2D(Collision2D c)兩邊都不是 Trigger會被擋住、彈開踩敵人、撞牆
    OnTriggerEnter2D(Collider2D other)至少一邊勾 Is Trigger穿過去，只觸發事件金幣、終點、陷阱區

    兩種事件都要求至少一方有 Rigidbody2D。另外還有 Stay（持續接觸）和 Exit（離開）版本。

    Tag 和 Layer 的分工：Tag 回答「這是什麼」，用 CompareTag("Player") 判斷。Layer 決定「誰跟誰會碰撞」和射線檢測範圍，在 Project Settings → Physics 2D → Layer Collision Matrix 設定。

    常見錯誤碰撞沒反應、角色亂翻

    • 寫成 3D 版本：OnTriggerEnter(Collider other) 是 3D 物理用的，2D 物件永遠不會呼叫。名稱和參數都要有 2D。
    • 參數型別寫反：Trigger 收 Collider2D，Collision 收 Collision2D。
    • 雙方都沒有 Rigidbody2D：事件不會觸發。金幣可以不加，但玩家一定要有。
    • 角色一跳就翻倒：忘了勾 Freeze Rotation Z。
    • 角色黏在牆上掉不下來：建立 Physics Material 2D，Friction 設 0，放到玩家的 Collider 上。
    • 用 transform.position 移動 Dynamic 剛體：等於瞬間移動，容易穿牆，也會和物理引擎打架。
    • 舊教學的 rb.velocity：Unity 6 會出現過時警告，改成 rb.linearVelocity。

    動手練習二段跳

    讓角色在空中可以再跳一次，落地後重置次數。提示：用 int jumpsLeft，在地面上時設回 2，每跳一次減 1。

    看參考答案

    加上 linearVelocity.y <= 0.01f 是為了避免剛起跳的那幾幀還碰著地面，次數又被補滿。

    LV.07 · Prefab 與生成

    用 Prefab 量產子彈、金幣和敵人

    遊戲裡大量重複出現的東西不會一個一個手擺。做好一個藍圖（Prefab），再用程式在需要的時候生出來。

    Prefab 是物件的藍圖

    • 建立：在 Hierarchy 做好一個物件（圖片、Collider、腳本都裝好），把它拖到 Project 視窗，就變成 Prefab，圖示是藍色方塊。
    • 編輯：雙擊 Prefab 進入編輯模式，改完之後，場景中所有用這個 Prefab 的物件都會一起更新。
    • 覆寫：在場景中單獨修改某一個實例，Inspector 會顯示粗體。按 Overrides → Apply All 可以寫回 Prefab。

    Instantiate 生成、Destroy 刪除

    子彈 Prefab 要有：SpriteRenderer、勾了 Is Trigger 的 CircleCollider2D、Body Type 設為 Kinematic 的 Rigidbody2D，再掛 Bullet。

    TryGetComponent(out EnemyHealth enemy) 的意思是「對方身上有 EnemyHealth 的話，放進 enemy 變數並回傳 true」。比先 GetComponent 再判斷 null 更簡潔。

    生成器：定時掉金幣

    Random.Range 有個陷阱：整數版不包含最大值，Random.Range(0, 3) 只會得到 0、1、2；小數版包含最大值。拿整數版當陣列索引剛好很方便：Random.Range(0, arr.Length)。

    常見錯誤生成與刪除

    • 拖到欄位的是場景裡的物件，不是 Prefab：那個物件一被刪除，就會出現 MissingReferenceException。欄位要從 Project 視窗拖 Prefab 進去。
    • Destroy(this) 和 Destroy(gameObject) 搞混：this 只刪掉這個腳本元件，物件還在。
    • 生成的物件從不清理：子彈飛出畫面後還在跑，數量一多就變卡。記得設壽命或飛出範圍就刪。
    • Random 名稱衝突：同時寫了 using System; 時，Random 會出現 CS0104 模糊參考，改寫成 UnityEngine.Random.Range(...)。

    動手練習往面向的方向射擊

    目前子彈永遠往右飛。改成：角色面向左邊時（SpriteRenderer.flipX 為 true）子彈往左飛。提示：Instantiate 會回傳生成的 GameObject，可以拿它的 Bullet 元件設定方向。

    LV.09 · 進階技巧

    協程、事件、ScriptableObject，再加動畫和音效

    這幾個工具能讓程式更整齊：等待一段時間、讓腳本彼此不用綁死、把數值設定獨立出來。最後補上讓遊戲有生命感的動畫和音效。

    協程 Coroutine：會等待的方法

    你在 Python 用過 yield 的話，協程就是同一個概念：方法執行到 yield 會先暫停，下次再從那裡繼續。Unity 會幫你在適當的時間喚醒它。

    寫法等待多久
    yield return null;等到下一幀
    yield return new WaitForSeconds(1f);遊戲時間 1 秒，暫停時也會停
    yield return new WaitForSecondsRealtime(1f);真實時間 1 秒，暫停選單的動畫用這個
    yield return new WaitForFixedUpdate();等到下一次物理更新

    事件：讓腳本不用互相認識

    玩家受傷時，血條 UI、音效、畫面震動都要反應。與其讓 PlayerHealth 一個一個去呼叫它們，不如發出一個事件，想知道的人自己來訂閱。

    ScriptableObject：把數值做成資料檔

    史萊姆、蝙蝠、骷髏用同一支敵人腳本，只是數值不同。把數值放在 ScriptableObject 裡，就能在 Project 視窗建立好幾份設定檔，讓企劃直接調數值，不用碰程式。

    存檔後在 Project 右鍵 → Create → Game → Enemy Data 就能建立資料檔。敵人腳本裡宣告 [SerializeField] private EnemyData data;，再用 data.maxHp 讀取。

    動畫和音效入門

    Animator：把一組 Sprite 圖片拖進 Scene，Unity 會自動建立動畫片段（Animation Clip）和 Animator Controller。在 Animator 視窗加上參數（例如 float Speed、bool IsGrounded），用箭頭連接狀態並設定切換條件，再由程式更新參數：

    音效：物件加上 AudioSource 元件，短音效用 PlayOneShot，可以重疊播放：

    常見錯誤進階工具的坑

    • 直接呼叫 FlashRoutine()：什麼事都不會發生，協程一定要用 StartCoroutine(...) 啟動。
    • 物件被停用，協程也停了：SetActive(false) 或物件被刪除時，它身上的協程會全部中止。
    • 訂閱了事件卻沒取消：物件被刪除後，事件仍會呼叫它，出現 MissingReferenceException。+= 和 -= 要成對出現。
    • Animator 參數名稱拼錯：不會出現紅字，只有黃色警告 Parameter 'speed' does not exist，動畫就是不切換。
    • 在 Play 模式中修改 ScriptableObject：和一般物件不同，修改會被保存下來。執行中不要用程式改它的數值，要改就先複製到自己的欄位。

    動手練習受傷後無敵 1.5 秒

    修改 PlayerHealth：受傷後 1.5 秒內再被打不扣血。提示：用一個 bool isInvincible，在協程裡設成 true，等待後設回 false。

    總專案：做出一關完整的 2D 平台遊戲

    • 搭好場景：Tilemap 地板、Ground 圖層、玩家物件
    • 玩家可以左右移動、跳躍，掉出地圖會 Game Over

    步驟 1：搭場景

    1. Hierarchy 右鍵 → 2D Object → Tilemap → Rectangular。開啟 Window → 2D → Tile Palette，建立調色盤，把地形圖片拖進去，就能像畫圖一樣刷地板。

    4. 玩家物件：SpriteRenderer、CapsuleCollider2D、Rigidbody2D（Gravity Scale 3、Freeze Rotation Z、Collision Detection 設 Continuous、Interpolate 設 Interpolate）。Tag 設為 Player，底下建立 GroundCheck 子物件。

    LV.11 · 遊戲類型 · 解謎

    推箱子：格子移動、推箱、悔一步

    解謎遊戲的核心是「格子」與「規則」。這一章用推箱子（Sokoban）示範三個常用技巧：把資料和畫面分開、推之前先檢查、用 Command 模式做悔一步。

    邏輯在格子上，畫面跟著格子

    不要用 Rigidbody2D 推箱子，物理引擎會讓箱子歪掉、滑動。解謎遊戲通常自己記住「誰在第幾格」（Vector2Int），規則全部用整數格子判斷，最後才把物件放到格子中心 (x + 0.5, y + 0.5)。

    場景通常有兩張 Tilemap：一張畫牆壁（Walls）、一張畫目標格（Goals）。用 walls.HasTile(new Vector3Int(x, y, 0)) 問某一格是不是牆。

    推箱子的完整規則

    1. 算出目標格 target = pos + dir，是牆就不動。
    2. 目標格上有箱子的話，再看箱子後面那一格 target + dir：是牆或另一個箱子就推不動。
    3. 可以推的話先移動箱子，勇者再前進。
    4. 每次移動後檢查：所有箱子都在目標格上就過關。

    箱子要有 BoxCollider2D 和 Tag「Box」，但不需要 Rigidbody2D。Vector2Int.FloorToInt 會把小數位置無條件捨去成格子座標。

    悔一步：Command 模式

    Unity 官方的 Design Patterns 教學用 Command 模式做悔一步：把每個動作包成一個物件，裡面有 Execute() 和 Undo()，做過的動作推進 Stack。按悔一步時 Pop 出最後一個，呼叫它的 Undo。

    遊戲裡的 11-5 用比較簡單的「紀錄類別」做同一件事，概念一樣：改變之前先記下原本的樣子。

    用文字檔蓋關卡

    關卡寫成字串，例如 # 牆、o 目標、B 箱子、P 玩家，用雙層迴圈讀進來。真實專案可以把關卡放在 TextAsset（拖進 Inspector 的 .txt 檔），用 levelText.text.Split('\n') 拆成每一行。記得字串第 0 行在最上面，所以 y = 行數 - 1 - row。

    常見錯誤推箱子

    • 只更新 pos 沒更新 transform：資料變了，畫面沒動。
    • 沒檢查箱子後面：箱子被推進牆裡，或兩個箱子疊在一起。
    • 悔一步沒存箱子的位置：玩家退回去了，箱子留在原地。
    • Stack 空的時候 Pop：InvalidOperationException: Stack empty，先檢查 Count。
    • 勝利條件每一幀都觸發：用一個 bool 記住已經過關。

    動手練習加上「重做」

    在 CommandInvoker 加第二個 Stack redo：Undo 時把指令推進 redo，按 Y 時從 redo Pop 出來再 Execute 一次。新的動作發生時要清空 redo。

    LV.12 · 遊戲類型 · 沙盒

    方塊沙盒：滑鼠、Tilemap、存檔

    沙盒遊戲讓玩家自由改造世界。這一章學三件事：把滑鼠位置換成格子、用 Tilemap 放和挖方塊、用 JSON 把世界存起來。

    三種座標

    座標單位怎麼拿到
    螢幕座標像素，左下角是 (0, 0)Mouse.current.position.ReadValue()
    世界座標Unity 單位（格子）Camera.main.ScreenToWorldPoint(螢幕座標)
    格子座標整數，Vector3Inttilemap.WorldToCell(世界座標)

    正交（Orthographic）攝影機時，ScreenToWorldPoint 的 z 不影響 x、y；透視攝影機要把 z 設成「攝影機到畫面的距離」，例如攝影機在 z = -10 就填 10。換算完記得把 z 設回 0。

    放方塊與挖方塊

    Tile 要先在 Project 視窗建立：把圖片拖進 Tile Palette 視窗會自動產生 Tile 資產（.asset），再拖進 palette 陣列。

    如果有 UI 按鈕疊在畫面上，點按鈕時也會蓋到方塊。用 EventSystem.current.IsPointerOverGameObject() 檢查滑鼠是不是在 UI 上。

    存檔：JsonUtility + PlayerPrefs

    JsonUtility 只會存 public（或 [SerializeField]）欄位，類別要加 [System.Serializable]；它不支援 Dictionary，所以這裡用兩個 List。PlayerPrefs 適合小資料，世界很大時改用 File.WriteAllText(Application.persistentDataPath + "/world.json", json) 存成檔案。

    常見錯誤沙盒

    • 直接把螢幕座標當世界座標：物件飛到幾百格外。
    • SetTile 傳 Vector3：要先 WorldToCell 換成 Vector3Int。
    • 按住拖曳時 wasPressedThisFrame 只放一塊：想要「拖曳連續蓋」就改用 isPressed，並避免同一格重複放。
    • Dictionary 的 key 打錯：KeyNotFoundException，先用 ContainsKey 或 TryGetValue。
    • FromJson 忘了型別：要寫 FromJson<WorldData>(json)。

    LV.13 · 遊戲類型 · 射擊

    太空射擊：物件池、波次、射擊模式

    射擊遊戲同時有幾十顆子彈和敵人，效能和節奏最重要。這一章學物件池、用協程排敵人波次、用 enum 切換武器，以及用 PlayerPrefs 存最高分。

    物件池：Unity 內建的 ObjectPool<T>

    不斷 Instantiate / Destroy 會產生記憶體垃圾，GC 回收時遊戲會卡一下。Unity 2021 之後內建 UnityEngine.Pool.ObjectPool<T>：Get() 拿一個（池子空了會自動建立新的），Release() 還回去。

    () => ... 是 lambda（匿名函式），遊戲裡的直譯器不支援，所以 13-1 用 Queue<GameObject> 手寫同樣的概念。collectionCheck: true 會在你重複 Release 同一顆子彈時報錯，開發時建議打開。

    敵人波次：協程

    波次資料多的時候，可以做成 ScriptableObject（每一波的敵人種類、數量、間隔），企劃不用改程式就能調整難度。

    移動模式與射擊模式

    • S 形：x = startX + Mathf.Sin(Time.time * 頻率) * 幅度。
    • 朝玩家衝刺：(player.position - transform.position).normalized * speed。
    • 射擊模式：enum FireMode { Single, Spread, Laser } 搭配 switch；散射用不同方向的向量，或用 Quaternion.Euler(0, 0, 角度) * Vector3.up 旋轉方向。
    • 最高分：PlayerPrefs.SetInt("best", Mathf.Max(best, score))。

    常見錯誤射擊遊戲

    • 物件池拿出來沒放回去：池子用完就出錯或一直建立新物件。
    • 重複 Release 同一個物件：時間到和撞到敵人在同一幀發生，要先檢查 gameObject.activeSelf。
    • 重複使用的子彈沒有重設狀態：上一輪的速度、血量還在，在 OnEnable 裡重設。
    • 協程裡忘了 yield：整波敵人在同一幀全部出現。
    • 兩個 if 互相抵消：切換 enum 時用 if / else 或三元運算子。

    LV.14 · 遊戲類型 · 塔防

    塔防：路徑點、找最近的敵人、狀態機

    塔防遊戲的三個基本系統：敵人沿路前進、塔自動瞄準、玩家花錢蓋塔。最後介紹狀態機，這也是 RPG 敵人 AI 最常用的寫法。

    路徑點（Waypoints）

    在路線的每個轉角放一個空物件，依序拖進敵人的 Transform[] waypoints。敵人用 MoveTowards 走向目前的點，距離夠近就換下一個。比較浮點數時不要用 ==，用「距離小於一個很小的數」。

    生成的敵人（Prefab）沒辦法在 Inspector 直接拖場景裡的路徑點。常見做法是由生成器在 Instantiate 之後把 waypoints 傳給敵人，或把路徑做成一個 Path 元件讓敵人去找。複雜地形可以改用 NavMesh 或 A* 尋路。

    塔：找範圍內最近的敵人

    用 sqrMagnitude（距離的平方）比較大小可以省掉開根號，結果一樣。很多塔防會讓玩家選瞄準規則：最近、血最少、走最遠的，只要換掉比較的條件。

    狀態機（Finite State Machine）

    把物件可能的狀態列成 enum，每一幀只執行目前狀態的程式，滿足條件就切換。好處是每種狀態的程式分開，不會變成一大串互相糾纏的 if。RPG 的敵人通常是：巡邏 → 發現玩家就追擊 → 距離夠近就攻擊 → 玩家跑遠就回去巡邏。

    追擊的「放棄距離」比「發現距離」大一點（這裡是 1.5 倍），可以避免玩家剛好站在邊界時敵人一直切來切去。

    常見錯誤塔防

    • 每一幀都 index++：路徑點全部被跳過，要先判斷到了沒。
    • 走到終點沒刪除：敵人停在終點，每一幀都扣一次血。
    • OverlapCircleAll 沒指定圖層：塔把自己也算成目標。
    • 直接拿 hits[0]：陣列順序和距離無關。
    • 狀態裡的計時器沒倒數：物件永遠卡在某個狀態。
    • 蓋塔沒檢查：路上、已經有塔的格子、錢不夠，都要先擋掉。
